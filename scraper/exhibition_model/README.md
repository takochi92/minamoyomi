# 平和島・画像内通過の試作モデル

艇番の標準色は **1＝白、2＝黒、3＝赤、4＝青、5＝黄、6＝緑**。
ヘルメット・カポック・艇の枠番を併用する方針だが、v1の実装はヘルメット周辺の色による推定。カポック全体や数字OCRまで実装済みとは言わない。赤い服の一部を拾って黒艇を赤艇と誤認する例があり、明瞭な複数点以外は採用しない。

`pilot-v1.npz` は照合済み1Rの艇首周辺73×73pxの輝度テンプレート18個とテロップの色マスク。元画像由来のテンプレートなので、取得・利用条件を確認するまではローカルだけに保管し、GitHub・サイトへ配布しない。リポジトリには指紋・設定・検証結果だけを保存する。動画・音声・配信キーも公開しない。1Rを種、2Rを調整用として、実装・設定・重みのSHAを凍結してから3Rの独立ラベルと比較した。実装ファイルと設定の改変は読込時に拒否する。

CIは元画像のテンプレートを使わず、合成配列で指紋・座標・欠測・重複を検査する。実映像の精度は、別に保存したローカルの実行結果で評価する。

v1の自動候補は2Rで2/6艇、未使用3Rで1/6艇のみ。3Rの採用艇は5号艇。これは小さい同日試料の診断であり、全レース精度・校正済み時間・機力順位の保証ではない。`automatic_publication_enabled=false`。本番の照合済み参考値とは別に扱う。

ユーザー提案の時間帯も有力。今日2〜12Rの検出した1マーク場面は、元動画開始からおおむね242〜252秒付近だった。ただしテロップ検出の粒度・フェードも含む値で、艇の通過時間ではない。時間は探索範囲の優先順位に使い、固定秒数だけで1マークや艇番号を決めない。広告・再展示・中断・編集変更の可能性があるのでテロップと画面の確認を残す。

取得ツールには任意の探索時間帯を渡せる（例 `--window-start 225 --window-end 310`）。これは取得範囲を絞る機能だけで、場面や艇番の認定ではない。範囲外や長すぎる指定は拒否し、元のPTSを保存する。初期値は広めの候補区間のままにしている。

実測のローカル処理時間は2R約93秒、3R約91秒（初回の動画取得やブラウザ準備、掲載処理は含めない）。GitHubの通常Chrome試験では、配信APIから403を受けマスターを観測できなかった。地域・IP・ブラウザ条件のどれが原因かは未確定。認証キー抽出、ユーザーエージェント偽装やプロキシでの迂回は行っていない。現在の毎日ジョブは映像の公開登録確認まで。
