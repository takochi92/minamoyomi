# 平和島展示：艇の連続追跡と艇首推定の研究実装

2026-10-27。通常予想・買い目・集計・公開参考値の変更はない。新コードは非公開の解析候補を作る研究用。毎日の自動取得・正式タイムの自動公開が完成したという記録ではない。

## 実装した処理

1. OpenCV ZooのYOLOXで選手・船体の候補を検出する。一般物体モデルなので、レーシングボートをsurfboardと分類する例や、ターンマークをboatと誤検出する例がある。矩形の端を艇首先端と同一視しない。
2. 選手付近の白・黒・赤・青・黄・緑を照合する。通過順から艇番号を割り当てない。色の継続・移動量を検査し、不明は不明のまま保存する。
3. 色を確認できた複数地点を起点に、前後のコマを光学フローで連続追跡する。定期的に物体検出で追跡枠を更新する。複数起点の一致度も記録する。最長の軌跡を選ぶこと自体は、艇番号の正しさの証明にならない。
4. １・２Rの既存の艇首レビューから85枚の学習画像を作り、小型のCPU用ヒートマップモデルを学習した。３Rは調整・診断用。モデルの自信が高くても誤るため、艇首位置・光学フロー・重複通過も別々に検査する。
5. 原動画のdecoded PTS、固定A/B/C線、隣り合うコマの艇首を使って通過時刻を補間する。検出が抜けたコマを飛ばして時刻を作らない。複数の通過候補があれば不確定とする。
6. 同じ動画でも切り出し開始位置でコマ番号は変わる。`frame_binding`は動画SHA、時間基準、全コマのPTSと画像SHAを束ねる。観測・追跡・測定・比較の間で一致必須。古い指紋なしの結果は自動的に昇格させない。

`automatic_turn_v2.analyze_video(..., keypoint_weights=...)`で、原動画のシーン選択から追跡と艇首候補までを同じ一時画像内で接続した。一時画像は処理終了後に片付ける。元映像や派生モデルは公開リポジトリ外に保管する。スロー動画は表示用で、測定入力に戻さない。

## 実測と限界

| 試験 | ３地点がそろった艇数 | 備考 |
|---|---:|---|
| 凍結した旧v1・３R | 1/6 | 従来の未使用確認、その後３Rを調整用へ移行 |
| 検出＋地点ごとの色追跡v2・３R | 2/6 | 調整用。キャッシュされた粗候補を使用 |
| 旧v1・４R | 0/6 | 不検出・重複を含む |
| 地点ごとのv2・４R原動画入力 | 0/6 | 11地点の候補。シーン選択を含め約530秒。全艇測定は失敗 |
| 連続追跡＋学習艇首・３R | 6/6 | 調整用。原動画のシーン選択からの一貫試験ではない |

３Rの連続追跡は６艇で約6.3〜6.4秒の候補軌跡を生成。保存済みの既存レビューの18地点を画像で点検し、該当艇を追跡枠が捉えていた。ただし同じ担当による確認であり、新たな独立レビューや全コマの正解ラベルではない。６艇の測定精度・毎日の検出率を示す数字ではない。

同じ画像書き出しに指紋を付けて再実行し、連続追跡から学習艇首へ接続した３Rでは６艇・18地点がそろった。既存の２AIレビュー平均に対し通過時刻差の最大0.02122秒、入口区間差の最大0.02214秒、出口区間差の最大0.00390秒。ただし３Rは開発中に使ったレースであり、比較先もAIによる映像内の参考測定で、実走時間の正解ではない。追跡約518秒、艇首測定約15秒に加え、粗候補生成の時間が別にかかる。未使用レース・ライブでの性能として宣伝しない。

既存３Rの既知通過付近54枚では、艇首位置の中央値誤差が粗候補3.90pxから学習モデル2.51pxになった一方、90パーセンタイル12.94px、最大25.71px。これは通過付近を事前に指定した条件付きの位置推定比較であり、原動画から全艇を自動測定した精度ではない。54枚すべてが内部の自信基準を通ったので、この基準だけでは誤りを排除できない。入口の丸い船首先端で、既存レビューとの位置定義差・モデルの偏りを含む可能性があり、どちらが正しいと断定しない。

統合した新方式は別途５Rで試験する。設定・係数の指紋は `research/exhibition-video/recognition-v2-20261027/` に保存。候補の有無と正確さは別指標であり、未検出も６艇の分母に残す。同じ日の映像だけでは別日の天候・画角への一般化は分からない。

## 再実行

Python、ffmpeg/ffprobe、任意のOpenCV・NumPy・SciPyとCPU版PyTorchが必要。通常の更新ジョブにはPyTorchを追加していない。YOLOX重み、艇色モデル、艇首テンプレート、シーンテンプレート、学習済み艇首重みは非公開で別途必要。コードのcheckoutだけで取得・解析が完成するものではない。

```sh
python -m tools.automatic_turn_v2 \
  --video /private/05/replay.ts --private-parent /private/tmp \
  --detector /private/models/yolox-s.onnx \
  --colour-model /private/models/colour-v2.json \
  --bow-model /private/models/bow-v2.npz \
  --scene-model /private/models/pilot-v1.npz \
  --keypoint-weights /private/models/bow-heatmap-bound-v1.pt \
  --output /private/05/research-result.json
```

このコマンドは保存済みのローカル動画だけを処理する。外部の取得・常駐登録・公開はしない。各段階は `actor_track_review`、`measure_tracked_bows`、`benchmark_tracked_bows` で個別に再検証できる。既存レビューを比較に使う場合も原PTSと画像SHAが一致しなければ拒否する。

許可された外部取得環境が確定した場合のワーカー接続は `exhibition_pipeline --research-model-dir /private/models`。既定の解析方式は変えていない。５つの非公開モデル、解析コード、固定線設定の指紋をまとめて保存し、地点ごとの候補数と連続追跡からの候補数を別々に記録する。接続口を作ったことは取得先の許可・配置・毎日の無人実行の成功を意味しない。

検証：通常依存の全Pythonテスト295成功・11スキップ、任意のCPU画像解析テスト22成功、ワーカー接続などの追加対象17成功、`node worker/test.mjs`成功。全体テストの最初の実行はWindowsの既定文字コードcp932で既存３テストの読込に失敗し、`PYTHONUTF8=1`で再実行して通過した。テスト成功は映像解析精度の証明ではない。
