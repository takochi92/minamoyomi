# 平和島の展示ページ：公開運用と残作業

## 実装済みの自動処理

`tools/update_exhibition.py` が、公式プレイヤー自身の当日設定
`https://front.player.boatrace-cdn.jp/setting/vod/YYYYMMDD/04heiwajima/exhibition/setting.json`
を１回取得する。日付・場・Rとref_idの対応を検査し、存在するレースだけの公式プレイヤーリンクを保存する。

- チャットを開く必要はなく、ChatGPT/API・ブラウザのログイン状態に依存しない。
- レースの登録は、動画を最後まで取得・復号できたことや解析できたことを意味しない。
- 同じレースの既存の確認済み参考値を保存し、別日・別Rへコピーしない。
- 設定から消えた映像は登録未確認としてリンクを隠す。取得エラー時は既存レジストリを破壊しない。
- 公開物は小さなJSONと生成ページのみ。動画・配信鍵・署名付きURLをgitやサイトへ保存しない。
- 予想、買い目、モデル、実績、締切前購入記録へは書き込まない。

本日2026-10-26の実行で12Rの登録を確認。1〜3Rには独立照合済みの映像内参考値を保存。4〜12Rを計測完了と扱わない。

## 毎日の実行

`.github/workflows/exhibition.yml` は日本時間09:07〜18:52の15分間隔と20:17に公式設定を確認する。GitHubの予約実行は遅延し得る。`workflow_dispatch` のdateで過去日の再確認もできる。

普通の予想更新とは別の軽いジョブで、Python標準ライブラリだけを使う。concurrencyも分離し、通常の予想更新を取り消さない。登録情報をgitへ保存した後、サイトへの公開は次の既存の通常更新に任せる。展示ジョブ自身は古いサイト全体を再配信しない。認証情報の新規発行や外部AIサービス課金は行わない。

公開登録の検知時刻とサイト反映時刻は異なる。たとえば10:00の動画公開なら予定上の次の確認は10:07で、その後の通常更新・公開処理を待つ。GitHubの待ち時間もあるため掲載時刻を保証しない。解析動画生成の所要時間を実測したことはなく、この例はタイム解析完了時刻ではない。

```sh
python -m tools.update_exhibition --date 20261026
```

status.jsonには確認時刻、登録件数、確認済み参考件数、エラー分類を保存する。`automatic_video_analysis_enabled=false` と `automatic_video_analysis_state=not_implemented` を明記し、入口の自動更新をタイム解析の自動化と呼ばない。

## 無人の映像解析は未完成

公式プレイヤーの公開HTML・設定・配信SDKを確認した。プレイヤーが使う再生メタデータへ通常の認証なしHTTPリクエストを１度試したところ401だった。SDKのキーや認証情報を抜き出して再試行していない。この直接取得方法は停止した。

通常プレイヤーの視聴は可能だが、日々の無人運用に使う安定した取得経路・取得条件の確認が必要。その上で、艇番号・艇首先端・カメラずれ・遮蔽の自動認識を作り、別レースの基準ラベルと照合する必要がある。既存の人手指定CSRTは艇首計測器として使わず、今回の２AI目視レビューを自動検出実装済みと扱わない。

### 通常プレイヤー経由の追加検証

ブラウザで公式プレイヤーを通常再生し、そこで観測できた配信マスターから本日12Rの候補区間をローカル取得できた。直接APIの401を認証キー抽出で回避したものではない。`tools/capture_exhibition.py` は同じ通常の画面操作をサーバーで実行するための実装。HTTPSの通常取得、標準AES-128のローカル復号、サイズ・区間制限を行い、SAMPLE-AES/ライセンス保護形式は拒否する。

専用 `.github/workflows/exhibition-capture-test.yml` で2Rの通常取得をGitHub上でも試験したが、後述の403で失敗した。個人のログイン・ChatGPT・OpenAI APIは使わない。外部に残すのは日付・R・動画SHA・所要時間などの数値だけ。動画、署名付きURL、配信キーはジョブの一時領域だけに置き、アーティファクトへ含めない。

GitHub試験は正常に再生マスターを観測できず失敗した。診断はプレイヤー200・配信API403。手元の通常再生は可能でも、GitHub上の取得は成立していない。以後の捕捉試験は手動のみとし、同じアクセス拒否を自動で繰り返さない。原因を地域制限と断定せず、許可された実行環境と利用条件を確認する必要がある。

これは取得の検証であり、毎日のタイム自動掲載を有効にしたものではない。ローカルでは2Rの自動通過候補17か所が独立AI２担当の平均と約0.03秒以内で一致したが、1か所未検出と重複候補があり、服の色だけでは艇番号を誤認する例もある。参考値を無条件に公開しない。2Rは調整用へ移し、3Rを設定に使わない確認用として照合する。

凍結したv1は艇色照合と重複候補排除を通した場合2Rで2艇・3Rで1艇のみ。処理時間はそれぞれ約93秒・約91秒。検出した全候補を正式タイムにしない。2R・3Rは独立AI２担当の照合済み参考値を別に保存・表示する。自動モデルの結果は未公開の研究用。

2026-10-26 2〜12Rの映像を無人取得・解析した結果はない。このジョブは自動解析ができたふりをせず、未測定のままにする。次の取得経路が成立するまで、全12Rの毎日の自動タイム掲載は完成しない。

## 公開ページ

展示解析をメインナビのレースと狙い目の間へ配置。実績と根拠は１ページに統合し、研究集計とモデル説明は折り畳む。既存logic.htmlは同じ統合画面の説明を自動展開する。参考値は映像内の区間秒数と明示し、正式実走タイムや機力順位と表現しない。
