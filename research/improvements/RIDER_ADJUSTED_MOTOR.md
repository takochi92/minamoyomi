# 乗り手補正つきモーター評価（検証と実装）

## 何を確かめたか

モーターの展示タイムの成績には、乗った選手の腕が混ざっている。選手の「いつもの展示の速さ」を差し引いた数字のほうが、**乗り手が替わったあと**の成績を当てられるかを、公式の過去データだけで確かめた。

- データ：公式の競走成績・番組表（`history/`）。モーター番号つきの約14か月、乗り替わり 38,396 回（24場）
- やり方：同じモーター（場×世代×号機）で乗り手が替わった「次の節」を的にする。前の乗り手までの数字だけで予想する（未来の数字は使わない）
- 前半の期間で重みを決め、**後半の期間（未使用）**で確かめた
- 再現：`python -m tools.rider_adjust_eval`

## 結果（後半の期間）

次の乗り手の成績（3着内に入った割合 − コースと級別からの期待）との相関：

| 指標 | 相関 |
|---|---|
| 公式モーター2連率 | 0.104 |
| 展示・補正なし（半減14日＝いまの本番に近い形） | 0.149 |
| 展示・補正なし（半減45日） | 0.161 |
| **展示・乗り手補正（半減45日）** | **0.178** |
| 展示（乗り手補正）＋着順（乗り手補正） | 0.185 |

上位20%と下位20%のモーターに乗った「次の乗り手」の実績（期待との差、3着内率）：

| 指標 | 上位20% | 下位20% | 開き |
|---|---|---|---|
| 公式モーター2連率 | +3.5 | −1.8 | 5.3 |
| 展示・補正なし（半減14日） | +4.4 | −3.3 | 7.7 |
| 展示・乗り手補正（半減45日） | +4.8 | −4.2 | 9.0 |
| 展示補正＋着順補正 | +5.1 | −4.4 | 9.5 |

- 乗り手補正は、前半・後半のどちらでも、試したすべての設定で効いた（補正あり−なしの相関の差 +0.029、95%区間 +0.025〜+0.033）
- 古い節を軽くする（半減45日）ことも効いた。いまの「直近3節・半減14日」より、長めに見たほうが当たる
- 展示タイムそのものは、選手の基準だけで相関 0.57 まで説明できる。**補正なしの展示順位は、かなりの部分が選手の順位**
- 効果は確かだが大きくはない。上位20%でも、3着内率が期待より約5ポイント高い程度。**必ず当たるものではない**

## 実装（既定では出力しない）

- `scraper/premium_motor.py`
  - `rider_baselines()`：公式の期別の展示成績（`exstats.json.gz` の `term_profiles`）から、選手ごとの基準（秒）を作る。新しい期ほど重く、走数の少ない選手は 0 に寄せる
  - `build(..., rider_profiles=...)`：新しい評価 `adjusted`（乗り手補正つき展示）を足す。窓の中の終わった節すべて・半減45日・乗り手が2人以上
  - 既存の `exhibition`・`straight`・組み合わせ評価は変えていない
- `python -m scraper.premium_motor --with-rider-adjusted …` のときだけスナップショットに入る
- `supabase/functions/premium/logic.mjs`：`adjusted` を受け付けるようにした（先にこの関数を反映してから、夜間集計に `--with-rider-adjusted` を付ける。逆の順だとスナップショットが不正扱いになる）

## まだやっていないこと・注意

- 会員ページでの表示（`adjusted` をどう見せるか）は未着手
- 検証は `history/` の展示タイムだけ。直線・まわり足（オリジナル展示）は、過去データが少ないので未検証
- 本番の選手の基準は期ごとの集計なので、いま乗っている節の数字も少し含む（選手1人あたり数百走に対して数走。影響は小さいが、検証の「その日より前だけ」とは完全には同じでない）
- 映像の実測値はまだ入っていない。入れるときも、同じ検証（乗り替わり後の成績を当てられるか）を通す
- A〜D の境目（上位20%など）は既存の評価と同じ。S の条件も同じ
