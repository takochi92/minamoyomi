# 平和島１マーク計測・正式版の型枠 v1

## 今回できたもの

1. `scraper/turn_measurement.py`：艇首・艇尾の指定、固定線通過、コマ時刻、カメラ固定点、別担当者の照合、締切前固定を扱うschema2の検査・保存・小型表示部品。
2. `tools/build_turn_review.py` と `tools/turn_review/`：実際の平和島1Rの前後コマで、艇首・艇尾をクリックし、確認データを書き出すローカル確認画面。6艇×3線、341コマ、4倍拡大、1コマ送り、下書き読込。追跡点は最初は非表示。
3. 旧試験の出口通過後の静止による誤除外を修正。出口前の停止は引き続き除外。

**これは正式運用に向けた実装済みの型枠。全自動の測定サービスや公開開始ではない。** 本番の予想・画面・購入記録・集計とは未接続。公開のスイッチは初期値false。外部送信・動画の再掲載・既存更新処理への重い映像処理追加は行わない。

## ずれへの対策

| 問題 | 正式版での扱い | 実装状況 |
|---|---|---|
| 枠に選手・水しぶきが入り中央がずれる | 艇首と艇尾を指定し、中点を測定点にする | 手動指定・検査を実装。自動の艇体検出モデルは未実装 |
| 手作業で元の追跡点に引きずられる | 元の点は隠して指定し、後で重ねて確認 | 確認画面に実装 |
| 担当者により位置が違う | 別担当者2名の艇首・艇尾を個別に比較。不一致は再測定 | 検査実装。担当者の認証・権限管理は未接続 |
| 入口・出口を都合よく動かす | 設定を全艇共通で固定し、設定とレースの指紋に照合結果を結び付ける | 実装 |
| カメラ移動・ズーム | 非一直線の固定物3点以上を確認し、動いたフレームは中止 | 検査実装。固定物の自動検出は未実装 |
| 画面取得時刻と実フレームのずれ | 原本のデコードPTS×time_baseを使用 | 受入検査実装。動画原本からの抽出・配信接続は未接続 |
| コマ落ち・隠れ | 前後の間隔・通過方向・区間順・遮蔽を検査し、数値を出さない | 実装。遮蔽入力自体の自動認識は未実装 |
| 出口後に追跡が停止 | 測定が終わった後の静止を除外判定から外す | 旧試験で修正・テスト |
| 後から過去の計測を締切前実績にする | 取得・照合・保存時刻を確認し、締切後の保存と既存ファイルの上書きを拒否 | 保存関数に実装。実運用は信頼できるサーバー時刻・権限下で実行する |

### 位置の基準

艇首は船体の前端、艇尾は船体の後端。モーター・選手・飛沫は含めない。中点はその2点の算術平均で、船体の重心や水面投影の厳密な中心ではない。この操作上の定義を全艇で統一する。どちらかが見えなければ無理に推測しない。

暫定の検査値は、担当者間の端点差3px以内、固定物の位置差2px以内、通過前後0.12秒以内、コマ間隔に由来する区間差の半幅0.1秒以内。**これらは暫定の設計値であり、実映像で達成済みの精度保証ではない。** 端点位置の誤差・編集速度・遠近差は、このコマ間隔検査だけでは除けない。

### 時間と距離の基準

Aは進入の固定線、Bはマーク横の固定線、Cは出口の固定線。全艇で同じ設定を使う。実際の減速開始や直線への移行を毎艇推定する方式は、測定距離が変わるためv1には採用しない。

表示名は「入り」「出口」、単位は「映像内の区間秒数」。経路・操縦・カメラの遠近の影響を含むため、「出足順位」「エンジン点」「実走○秒」とは呼ばない。映像が編集上スローなら実時間との対応を別途調べる。0.5倍再生などのプレイヤー操作の時間と、動画内PTSを混同しない。

候補枠からの補間ではなく、艇体の端点を確認した通過前後の2コマで固定線を挟む。出力は小数1桁に丸めた一点の参考値にし、内部には両コマと時刻を残す。推測値で穴埋めしない。

## データと状態

| 項目 | 内容 |
|---|---|
| schema/method | `2` / `heiwajima-hull-gates-v1` |
| race_id | `YYYYMMDD-04-R`。場は平和島・１マークに限定 |
| captured_at/deadline/sealed_at | タイムゾーン付きの取得・締切・固定時刻 |
| evidence.source | 原動画sha256、`clock=decoded_pts`、整数比time_base |
| evidence.image_size/gates | 元画像サイズ、全艇共通のA/B/C固定線 |
| evidence.camera_reference | 非一直線の固定物3点以上の基準座標 |
| evidence.boats[].events | A/B/Cそれぞれの前後2コマ。id、整数pts、固定物座標、遮蔽確認 |
| reviews | 別担当者2名の識別名、照合時刻、全軌跡確認、艇首・艇尾ラベル、入力の指紋 |
| report | 入り・出口・理由。計算し直すので入力済みの秒数は信用しない |

`remeasure` → 数値なし、`checked_reference` → 手動照合した参考値。ただし照合が済んでも本番公開には進まない。`publication_ready` は、デプロイ側の明示的な公開設定、締切前の取得・照合・保存、全艇の検査通過が必要。入力JSONに「公開済み」と書いても効かない。

公開スイッチの有効化は、未使用レースでの性能評価と取得経路の実装後に別の変更として行う。確認者名だけでは本人認証を証明できないため、一般利用者から提出されたJSONを信頼して公開するAPIは作らない。現状のローカル確認ツールは開発担当者用。

`seal_record()` は全検査を通ったデータだけを排他的な新規作成で保存。既存データは変更しない。失敗して壊れたファイルも勝手に再作成しない。サーバー時刻の偽装や管理権限での改竄まで防ぐ暗号署名基盤ではない。

## 確認画面の使い方

```sh
python -m tools.build_turn_review \
  --frames <今回のローカル画像フォルダ> \
  --config research/improvements/HEIWAJIMA_TURN_PILOT.json \
  --tracks research/exhibition-video/heiwajima-20261026-1R/tracks.json \
  --report research/exhibition-video/heiwajima-20261026-1R/report.json \
  --output <確認用HTML>
```

1. 艇・線を選び、前後のコマを送る。必要なら４倍拡大。
2. 艇首・艇尾を指定し、通過前／通過後のコマを指定する。
3. 元の追跡点を重ねてずれを確認する。別担当者のラベルを見て同じ位置に合わせない。
4. 担当者と確認状況を付けてJSONを書き出す。読み直し可能。別の画像・設定の下書きは拒否。

今回のHTMLは画面キャプチャ由来の未校正時刻を保持する。書き出すのは `turn-review-draft-v1` で、schema2の公開レコードではない。PTSに昇格する変換機能は作らない。今回の手動指定例も単独担当者の例であり、照合済みデータではない。

## 自動化の進め方

1. 平和島で利用可能な動画取得方法と、締切前の提供時刻・所要時間を確認する。通常の更新ジョブと分離する。
2. 正確なコマ時刻、艇番号、１マーク区間、カメラ固定点を抽出。原本・設定の指紋を保存する。
3. この確認画面で艇首・艇尾・遮蔽の教師データを作る。CSRTは候補領域を探す用途に限定する。
4. 船体の領域分割と艇首・艇尾のキーポイント検出を比較する。水しぶき・選手を除外し、見えない端点を無条件に補完しない。検出不一致なら再検出し、それでも不明なら保留。
5. レース／日単位で学習用と未使用評価用を分離。同じ映像の隣接フレームを別の評価セットへ混ぜない。艇番号取り違え、端点誤差、通過時刻誤差、測定できた割合、誤掲載率を全件記録。
6. 初期評価の目安は未使用3日・20レース以上を確保し、時刻誤差の95パーセンタイル0.1秒以内を目標にする。これは合格済みの結果でも、統計的な十分性を保証する件数でもない。悪条件・見逃し・失敗の分母も示し、実測に応じて公開条件を改める。
7. まず手動照合付きの平和島限定版。その結果を見て自動公開の可否を決める。予想への採用はさらに別の未使用期間の検証が必要。

## 検証の範囲

Pythonは艇体の端点、時計、カメラ、照合の一致・改変、締切と保存、表示の漏れを検査。JavaScriptはスマホ縮尺／拡大時の座標、クリック、艇別コマ、下書き書出し、未読込画像の誤指定を検査。DOM代替による動作検査であり、ブラウザでの描画・スマホ実機操作の確認とは区別する。今回の画像案は静的な見本で、実ブラウザのスクリーンショットではない。
