# 改善の再検証データ

`REPORT.md` は考察、`improvements.json` は対応状況と未検証項目、`statistics.json.gz` は全比較区分・月別内訳・機歴・映像確認待ち一覧・仮想購入集計です。

```bash
python -m tools.research_review
python -m pytest -q tests
```

- `personal.comparisons`: 通常の単独展示1位との比較、同選手比較、低1位率群内の1位／非1位比較、0.03秒条件の追加比較。全条件を保存し、都合の良い区分だけを採用しません。
- `personal.strata`: 比較の分母・1着数・3着内数。構成調整の区分を保存。参照値は終了済み直前2期だけです。
- `motors`: 比較基準を前日以前だけで作り、節区切りを場の日程と保存済み公式開催名で補強。更新日は推定として明示します。直近2節にオリジナル展示を接続し、該当節がない場合は補完しません。
- `exhibition.overlap`: 複合条件同士の重複。独立した根拠として重複加点しません。
- `exhibition.video_review_queue`: 展示条件で選んだレースの映像確認欄。未確認はnull、映像での特徴は事後検証用で予想入力には使いません。この一覧だけでは全攻め試行の分母になりません。
- `forward_ledger`: 現行AI本線＋押さえの各100円仮想購入。入力・オッズ・予想の時刻と、締切前に固定した券を確認できたレースだけ評価。0件の場合ROIはnullです。モデル版×月の内訳を保存し、モデル変更を混ぜずに比較できます。サイトの実購入記録ではありません。

公式返還艇を含む券を返還し、スタート後の事故を自動返還しません。不成立で全額返還と断定できない結果は未決済に残します。公式説明: https://www.boatrace.jp/owsp/sp/extra/enjoy/guide/jiten/29/y_250.html

前向き仮想購入用のschema2を採用するのは、ワークフローが新コードで動き始めてからです。既存の旧データを昇格しません。毎朝の履歴ワークフローで研究データも再集計します。

探索の着率差は因果効果・回収率ではありません。場・コース・当時級別・全国勝率区分をそろえても、気象、対戦相手、機力、進入変化、同一レース内の相関などが残ります。比較可能な対象の割合を必ず併記します。推定がない少数区分も消さず保存します。
