# 平和島・展示１マークの映像計測試験（2026-10-26）

## 結論

本番未接続。平和島だけに限定した、手動で最初の艇枠を指定するCSRT追跡・固定線の通過時刻推定・不良追跡の除外を実装した。全艇自動認識でも、全レース自動取得でもない。

10月26日平和島1Rの終了済み展示リプレイで試した。操作ボタンを表示した最初の試行は、1号艇の追跡が再生UIに吸着した。操作表示を消して取り直すと6艇ともA/B/Cの通過候補を検出したが、目視で3号艇の追跡枠が艇体から水面側にずれている。2・5号艇は出口通過後の停止まで含める保守的な検査で除外された。**一般公開できると検証済みの計測は0艇。** 通過検出6/6を計測成功率とは表現しない。

計測区間を出口通過時点で閉じる改善、艇体中央と追跡枠中央の一致、未使用レースでの誤差検証が必要。現時点の候補秒数を出足順位・機力・予想確率や買い目へ転用しない。

- 出典：BOATCASTの平和島展示、2026-10-26・1R「トランスワードトロフィー ヤングVSベテランバトル」。映像内の表示「1周1マークリプレイ」を確認。
- 画面1280×720、動画本体の表示サイズ1920×1080、プレイヤー0.5倍速で観察。取得した動画内時刻を使い、作業時間をそのまま実走時間にはしない。
- 操作表示なし450枚、動画内245.057〜270.080秒。各画像のキャプチャ直前・直後のcurrentTimeを保存し、その中点をコマの参考時刻とする。デコードされた当該フレームのPTSそのものではなく、同期精度未校正。
- A：x=500、y=470〜630、左から右。B：y=360、x=740〜980、下から上。C：x=500、y=170〜310、右から左。全艇共通。
- Aは画面上の固定進入線で、実際の減速開始を検出したものではない。Bはマーク横の画面線、Cは固定出口線で、全艇の直線移行時点を検出したものではない。
- 基準点はCSRT追跡枠中央。要求する艇首・艇尾の中点との一致は未完了。物理距離・透視変換・カメラ移動・映像の編集速度は未校正。

## 再検査

映像をリポジトリやサイトへ転載しない。保存した座標・時刻・設定だけで品質判定を再実行できる。

```sh
python tools/heiwajima_turn_pilot.py \
  --config research/improvements/HEIWAJIMA_TURN_PILOT.json \
  --tracks research/exhibition-video/heiwajima-20261026-1R/tracks.json \
  --output /tmp/heiwajima-turn-review
```

ローカル画像から追跡を再計算するときだけ、別環境に `opencv-contrib-python-headless==4.12.0.88` を導入し、`--tracks` の代わりに `--frames <frames.jsonと画像のディレクトリ>` を指定する。通常のrequirements・予想更新処理には追加しない。リモート映像のダウンローダーやサービスへの連続取得処理は含まない。

品質判定は6艇の識別、同一画面サイズ、時刻の逆転／0.2秒超の欠落、追跡失敗、操作表示との重なり、静止、指定方向と線の範囲、各通過が1回でA→B→Cとなることを検査。全て通っても `needs_manual_review` で、`publication_ready` と `prediction_used` は必ずfalse。人による一致検査やカメラ校正の代わりにはならない。結果の一部だけを成功として宣伝しない。
